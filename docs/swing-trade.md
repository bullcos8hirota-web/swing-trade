# 設計メモ — スイングトレード支援アプリ

`swing/` に置いた、SBI証券での日本株スイングトレードを支援するアプリの設計。
録音メモアプリ(`app/`)と同じ構成(React + Vite + TypeScript + Tailwind + Dexie + Zustand)で、
サーバーを持たずブラウザ内で完結する。スマホでの利用を前提としたPWA。

## 1. 何を解く道具か

スイングトレードで負ける原因の多くは、銘柄選び以前の以下にある。

- 損切り位置を決めずに買う
- 資金に対して大きすぎる株数を買う
- 買った理由を覚えていないので、同じ失敗を繰り返す

そこでこのアプリは「予測」ではなく、**判断材料の整理**と**ルールの固定**を担当する。

1. チャートから読み取れる事実を並べる(監視・銘柄タブ)
2. 許容損失から株数を逆算する(売買プラン)
3. 決めたラインへの到達を知らせる(建玉タブ)
4. 結果を集計して振り返る(記録タブ)

株価の自動取得はしない。証券会社サイトのスクレイピングは規約上の問題があり、
無料の株価APIも日本株の日足は安定して取れないため、CSV取り込みと手入力に振り切っている。

## 2. 構成

```
swing/src/
├── lib/
│   ├── market/
│   │   ├── indicators.ts   SMA/EMA/RSI/MACD/ボリンジャー/ATR/高安/クロス判定
│   │   ├── signals.ts      指標のスナップショットとシグナル抽出、スコア化
│   │   ├── csv.ts          CSVパーサ、株価CSV、SBI取引履歴CSV、FIFO突き合わせ
│   │   ├── sampleData.ts   動作確認用の架空データ生成(乱数の種を固定)
│   │   └── types.ts
│   ├── money/
│   │   ├── position.ts     株数の逆算、損切り候補、売買プラン、トレーリング
│   │   ├── fees.ts         手数料(0円 / 段階テーブル)、譲渡益税
│   │   ├── tick.ts         呼値の丸め
│   │   ├── trade.ts        トレードの型と損益・R倍の計算
│   │   └── stats.ts        勝率・期待値・PF・最大DD・資産曲線
│   ├── db/                 Dexie(stocks / series / trades / settings)
│   └── format.ts           円・%・日付の表示整形
├── stores/appStore.ts      Zustand。起動時に全件読み込み、更新はDexieと同時
└── components/             タブごとのビュー + SVGチャート
```

指標の計算結果は「入力と同じ長さの配列、未確定はnull」で統一している。
配列の添字がそのままローソク足の添字になるので、描画と判定でズレない。

## 3. シグナルとスコア

`analyze()` が中立50点から加減点して0〜100に収める。点数はチャートの状態の要約であり、
売買の指示ではない(UIにもそう書いてある)。

| シグナル | 条件 | 点 |
| --- | --- | --- |
| 上昇トレンド | 終値 > 25日線 > 75日線 | +14 |
| 下降トレンド | 終値 < 25日線 < 75日線 | -18 |
| 25日線の向き | 直近5日の傾き ±0.1%/日 | ±8 |
| ゴールデン/デッドクロス | 5日線と25日線の交差(3日以内) | ±12 |
| 押し目 | 上昇トレンド中、25日線との乖離±3%以内 | +9〜16 |
| 20日高値ブレイク | 前日までの20日高値を終値で更新 | +10(出来高1.5倍以上で+18) |
| 20日安値割れ | 前日までの20日安値を終値で下回る | -16 |
| MACD好転 | MACDがシグナルを上抜け(3日以内) | +10 |
| RSI | 30未満 / 75超 | +8 / -10 |
| 過熱 | 25日線から+15%超 | -12 |
| 出来高薄 | 20日平均の60%未満 | -6 |
| 低ボラ | ATRが終値の1.2%未満 | -4 |

20日高値は**前日まで**で計算する。当日の高値を含めると必ず自分自身を更新してしまうため。

## 4. 資金管理

```
許容損失   = 運用資金 × リスク%
1株リスク  = エントリー価格 - 損切り価格
株数       = floor(許容損失 ÷ 1株リスク ÷ 売買単位) × 売買単位
投入上限   = floor(運用資金 × 上限% ÷ 価格 ÷ 売買単位) × 売買単位
発注株数   = min(株数, 投入上限)
```

単元株(100株)では1単元すら買えないことがあるため、
「リスク超過」と「1銘柄の投入上限」を区別して、S株(単元未満株)の検討を促す。

損切り候補はATR×n・直近5日安値の少し下・25日線の少し下の3つ。
利確目標は損切り幅 × 利確倍率(既定2倍)。価格は呼値に丸め、損切りは切り下げ、利確は切り上げる。

## 5. トレード記録

- 売買プラン画面から建玉として記録(エントリー根拠はシグナル名から自動で入る)
- 手仕舞い時に売却日・価格を入れると確定損益とR倍が出る
- SBI証券の取引履歴CSVはFIFOで突き合わせ、分割売却は複数トレードに分ける。手数料は株数で按分する
- 集計は勝率・平均利益/損失・ペイオフレシオ・PF・期待値(円とR)・最大DD・最大連敗・平均保有日数

## 6. テスト

`npm test`(vitest)で、指標・資金計算・CSV解析・シグナル判定・サンプルデータの形を検証している。
UIは含めず、判断を左右するロジックだけを対象にしている。

## 7. スマホ対応

ネイティブアプリではなくPWAにしている。ストア審査なしで配布でき、
コードが1つで済み、ホーム画面から起動すればアプリと同じ見え方になるため。

- ナビゲーションは幅640px未満で画面下のタブバー、それ以上で上部タブ(`components/Layout/`)
- 入力欄は16px以上。これを下回るとiOS Safariがフォーカス時に勝手に拡大する
- ボタンとタブは高さ44px以上を確保
- セーフエリア(`env(safe-area-inset-*)`)分の余白をヘッダーと下タブに入れる
- チャートは画面幅で表示本数を変える(スマホ60本 / それ以上120本)。横スクロール時は直近の足が見える位置に寄せる
- Service Workerでアプリシェルをキャッシュし、オフラインでも起動する
- IndexedDBが使えない環境(プライベートブラウズ等)では、メモリ上だけで動かして画面上部で知らせる

## 8. 学習機能

「操作しながら株の用語を覚える」ことを目的に、解説を後付けのヘルプではなく画面に埋め込んでいる。

- `lib/learn/glossary.ts` — 用語集のデータ。1語ごとに「一行説明」「本文」「このアプリでは」「関連語」を持つ
- `components/Learn/GlossaryProvider.tsx` — どの画面からでも `openTerm(id)` で解説シートを開ける。関連語をたどれるよう履歴を持つ
- `components/Learn/HelpButton.tsx` — 用語の横に置く「?」と、文中に置く下線リンク
- `lib/learn/signalTerms.ts` — シグナルID → 用語IDの対応表。判定結果から直接解説に飛べる
- `components/Learn/LearnView.tsx` — 学ぶタブ。流れ / チャートの型(サンプルデータの実チャート) / 資金管理(連敗シミュレーター) / バフェット / 用語集
- `lib/learn/buffett.ts` + `components/Learn/BuffettSection.tsx` — バリュー投資の観点。ROE・営業利益率・自己資本比率・EPS成長率・有利子負債÷営業利益・PER・FCFを入力して判定する。判定は純関数にしてテストしている
- `lib/learn/quiz.ts` + `components/Learn/QuizSection.tsx` — 20問からランダムに5問出す理解度チェック。解説から用語集へ飛べる
- `components/Learn/FundamentalsForm.tsx` / `FundamentalsResult.tsx` — 財務データの入力と判定表示。学ぶタブの練習用チェッカーと、銘柄ごとの企業カルテで共用する
- `components/Symbol/CompanyCard.tsx` — 銘柄に紐づく企業カルテ。`Stock.fundamentals` としてDexieに保存する(索引は張っていないのでスキーマ変更は不要)

監視タブには財務スコア(`evaluateFundamentals` の点数)を表示し、
「中身が良い」「中身◎ × チャート◎」で絞り込めるようにしている。
チャートのスコアと財務スコアは別物として並べ、掛け合わせるかどうかは利用者が選ぶ。

バフェット流はスイングトレードと時間軸が正反対(数日 vs 10年)なので、
「併用するなら、何を買うかは企業の中身で絞り、いつ買うかはチャートで測る」
「途中で目的をすり替えると塩漬けになる」という注意を本文に明記している。

テストで、用語IDの重複・関連語のリンク切れ・シグナルに対応する解説の欠落を防いでいる。
